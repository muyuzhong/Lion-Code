Why Lion Code

大多数 Coding Agent 止步于“调通工具”
Lion Code 直面长任务的真正瓶颈

模型写代码已经很强，但真正决定 Agent 能否用于真实工程的，是工具执行的安全性、数十轮对话后的上下文效率，以及严谨的数据验证。

1. 工具如何安全执行？ Fail-Closed 防线

模型在自主写代码时可能误删文件或越权执行。Lion Code 构建了四层防御矩阵（静态规则 → 人工门控 → PreToolUse Hook → 复合信任指纹）。

# 核心不变量：Hook 异常全部 Fail-Closed
✗ 禁止传入云凭证与 API Key (仅白名单 PATH/HOME)
✓ 信任指纹 = 根目录 + Hook ID + 配置哈希 + 脚本内容哈希

2. 长任务上下文如何不爆炸？ 前缀缓存感知

不是快溢出时才草率做一次摘要。5 级管线梯级处理（>30KB 自动落盘、动态预算、陈旧裁剪、空闲清理、同模型压缩）。

# 独创洞察：缓存仍热时延迟裁剪
⚡ 上次调用 <5min 时保留旧前缀，直到 75% 水位
✓ 避免改写前缀导致缓存失效，换取更高命中率

3. Provider 如何解耦自适应？ 单一异步生成器

纯 httpx 实现 Anthropic 与 OpenAI 兼容适配器，核心运行时零 SDK 导入。单一异步生成器循环驱动工具生命周期。

# 3 个每轮动态钩子，无需重建运行时
⚡ get_system() 动态切换 Plan 模式 / 约束提示
✓ get_tools() 动态发现 MCP / 激活 Skill

Architecture Deep Dive

清晰严谨的分层架构设计

通过 AST 门禁、_boundaries.py 与 import-linter 强制分层边界。Profile 只决定组装图，不把 feature 开关塞进全局配置。

lion_code/application/session.py 会话边界与前端事件桥接
Python 3.12+ 
# application/session.py
class LionCodingSession:
    def __init__(self, agent: MetaAgent, storage: SessionStorage):
        self.agent = agent
        self.storage = storage
        self.command_registry = CommandRegistry()
        self._register_builtin_commands()

    async def execute_turn(self, user_prompt: str) -> AsyncIterator[SessionEvent]:
        # 拦截斜杠命令 (如 /plan, /cost, /compact)
        if user_prompt.startswith("/"):
            async for event in self.command_registry.dispatch(user_prompt):
                yield event
            return

        # 启动 Agent Kernel 异步生成器
        async for event in self.agent.run(user_prompt):
            await self.storage.record_event(event) # JSONL 追加 + fsync
            yield self._bridge_to_session_event(event)
关键架构不变量：Session 边界负责把 CLI/TUI 的用户交互转化为规范事件流；斜杠命令不污染模型上下文历史，临时投影按需完成。
Safety & Permissions

Fail-Closed 分层工具安全防线

权限系统是分层的——没有单一机制拥有最终决定权。4 种渐进权限模式与 4 层物理防御叠加，彻底杜绝意外与恶意逃逸。

DEFAULT (默认)
渐进安全模式

只读操作（read_file）直接放行快路径；文件写入与危险 Shell 自动进入人工确认。

ACCEPT EDITS (--accept-edits)
文件修改免审

自动批准代码编辑与补丁写入，但破坏性 Shell（如 rm -rf, git push）仍然强制人工确认。

DON'T ASK (--dont-ask)
非交互 CI 模式

自动拒绝所有需要人工确认的敏感操作。专为无人值守 CI 门禁设计，避免流水线死锁挂起。

YOLO (--yolo)
隔离环境放行

跳过人工确认，仅限隔离沙箱使用。注意：项目级 Hook 信任指纹若不匹配，仍会强制确认。

四层防御叠加机制

1. 权限模式 (Permission Modes) 未知工具 → 默认拒绝
2. 人工确认门控 (Human Gating) 超时未应答 → 拒绝
3. PreToolUse Hook (子进程命令) 崩溃/超时/异常 → Fail-Closed 拒绝
4. 复合信任指纹 (Trust Registry) 内容哈希漂移 → 重新强制确认
关键设计：Hook 故障 ≠ 策略拒绝。当 Hook 脚本崩溃或超时，Lion Code 向 Agent 报告“基础设施故障”，而非“你的操作被策略拒绝”，彻底阻断模型将基础设施故障当成策略边界而试图试探绕过。

Context & Prefix Cache Engine

前缀缓存感知的
多级上下文管理管线

很多 Agent 每次压缩历史都会无情作废 Provider 的前缀缓存。Lion Code 在利用率达 60% 时，若感知到前缀缓存仍热（<5min），会延迟裁剪至 75%，换取显著更低的延迟与费用。

> 30 KB

Stage 2
动态预算
利用率 > 50%

根据剩余上下文空间收紧单次工具输出上限，保留首尾关键信息

Stage 3 · 核心独创
陈旧结果裁剪
利用率 > 60% / 75%

热缓存状态下延迟裁剪至 75%，保护已命中的前缀缓存块

Stage 4
空闲清理
空闲 > 5 分钟

检测到前缀缓存已自然冷却后，积极清理早期冗余工具结果

Stage 5
同模型全量摘要
利用率 > 85%
