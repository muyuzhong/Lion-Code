# Agent Notes（Lion Code）

> 本目录记录 Lion Code 的架构决策与简化提案。笔记不是真理来源——
> 代码与架构测试才是；笔记解释「为什么」，方便接手者不重复踩坑、不重复发明。

## 生命周期

| 目录 | 含义 |
| --- | --- |
| `proposed/` | 提案：有证据、待 owner 决策，尚未实现 |
| `implemented/` | 已落地：记录决策原因、落地点与验收证据 |
| `archived/` | 已归档：被完全取代或已无价值的旧实现笔记（原样保留，不再编辑） |

## 分类（class）

- `simplification/`：删除、折叠或降级真实存在的面（死代码、重复机制、投机泛化、手写轮子）
- `architecture/`：分层归属、边界、所有权契约
- `process/`：工程流程、门禁、验证方式
- `decision/`：负面决策（明确不做某件事的原因）

## 什么时候写

- 改动涉及非显然的设计取舍、不变量、删除理由，且代码本身无法表达时。
- 简化审计产生「删除什么、为什么安全」的证据链时。
- 不要为「一行 typo」「跑一次 knip」「这看起来很复杂」之类的薄猜测写笔记；
  小的本地清理用行内 `TODO(issue)`，大决策才用笔记。

## 格式

- 文件名：`.agents/notes/<lifecycle>/<class>/YYYY-MM-DD-简短主题.md`
- 一个文件只承载一个提案；结构参照：标题（`# Agent Note: <动作导向标题>`）、
  `Status: proposed`、`## Problem`（现状 + 消费者证据，区分生产/测试）、
  `## Proposal`（精确到删哪些符号/测试/文档）、`## Why not keep it` 或
  `## What we give up`（最强的反方论证）、`## Acceptance criteria`、
  `## Risks`（公共 API/行为变化、未来产品诉求）。
- 一个物理段落一行；链接用相对 Markdown 路径。
- 语言：与项目一致，正文中文，标识符与术语保留英文。

## 删除与取代规则

- 完全取代：把旧笔记的独特理由、备选方案、验收证据移入当前 owner 后，
  连同中文/英文副本一起删除，并修复所有入链。
- 部分取代：保留旧笔记，互相交叉链接，标注各自仍然有效的部分。
- 被拒绝的提案：只有当它不再阻止一个诱人错误时才能删除。
- add-then-remove 的功能：由 removal note 拥有删除历史，前提是功能已从
  生产代码、配置、schema、持久化/线格式、兼容行为中完全消失，
  且没有文档/测试把它当作可用能力。

## 门禁

- 改代码实现时，笔记要与实现一起更新或删除——笔记与代码不一致按缺陷处理。
- 只改笔记/文档时：至少跑 `git diff --check`；涉及架构契约时同步
  `.trellis/spec/backend/*` 与 `tests/architecture/*` 期望值。
